 ১. এক নজরে কী আছে
────────────────────────────────────────────────────────────────────
 • .env থেকে SMS credential AUTO-LOAD (কোনো হার্ডকোড key নেই)
 • OTP: 6 ডিজিট, 5 মিনিট মেয়াদ, HASH করে সেশনে রাখা হয় (প্লেইন না)
 • SMS OTP লিমিট: একই নম্বরে 30 মিনিটে সর্বোচ্চ 3 বার
 • জেনারেল SMS (নোটিফিকেশন): লিমিট ছাড়া — যেমন উত্তোলন অ্যালার্ট
 • LOG: সফল ও ব্যর্থ দুটোই লেখা হয়
 • নম্বর AUTO নরমালাইজ (mobile / phone দুটোই → 88 প্রিফিক্স)

 ৩. যেকোনো পেজ / মডিউলে চালু করা — শুধু ১টা লাইন
────────────────────────────────────────────────────────────────────
 require_once '<path>/Core/SmsConfig.php';

 এই একটা লাইন দিলেই সব constant + সব helper function চালু হয়ে যায়।
 ফাইলটা নিজেকে গার্ড করে (SMS_LOADED, function_exists) — তাই একাধিক
 বার include হলেও কোনো এরর হবে না, নিরাপদ।

 ▶ path কীভাবে বের করবেন (আপনার ফাইল কত গভীরে তার উপর নির্ভর):

   • রুট ফোল্ডারের পেজ (public_html/page.php):
       require_once __DIR__ . '/Core/SmsConfig.php';

   • ১ লেভেল গভীরে (Admin/page.php):
       require_once dirname(__DIR__) . '/Core/SmsConfig.php';

   • ২ লেভেল গভীরে (Modules/CashBox/Controller.php):
       require_once dirname(__DIR__, 2) . '/Core/SmsConfig.php';

   • ৩ লেভেল গভীরে (Modules/X/Controllers/Y.php):
       require_once dirname(__DIR__, 3) . '/Core/SmsConfig.php';

   dirname(__DIR__, N) মানে বর্তমান ফোল্ডার থেকে N ধাপ উপরে ওঠা,
   যতক্ষণ না রুট (যেখানে Core/ ফোল্ডার আছে) পাওয়া যায়।

 ৪. অন্য মডিউলে যোগ করার ৩টি ধাপ (উদাহরণসহ)
────────────────────────────────────────────────────────────────────
 ধাপ ১ — ফাইলের উপরে SmsConfig include করুন (path ঠিক করে):
   require_once dirname(__DIR__, 2) . '/Core/SmsConfig.php';

 ধাপ ২ — যা দরকার সেই helper ডাকুন:
   • OTP পাঠাতে:          otp_send_sms($phone, 'purpose');
   • নোটিফিকেশন পাঠাতে:    send_sms($phone, 'যেকোনো মেসেজ');

 ধাপ ৩ — best-effort হিসেবে try/catch এ মুড়ে দিন, যাতে SMS ব্যর্থ
         হলেও মূল কাজ (সেভ/আপডেট) না থামে:

   try {
       require_once dirname(__DIR__, 2) . '/Core/SmsConfig.php';
       if (function_exists('send_sms')) {
           send_sms($phone, "আপনার মেসেজ");
       }
   } catch (\Throwable $e) {
       error_log('MyModule SMS: ' . $e->getMessage());
   }

 ── বাস্তব উদাহরণ: একাধিক অ্যাডমিনকে নোটিফিকেশন ──
   $stmt = $conn->query("SELECT phone, mobile FROM users WHERE role='admin'");
   $rows = $stmt ? $stmt->fetchAll(PDO::FETCH_ASSOC) : [];

   $numbers = [];
   foreach ($rows as $r) {
       foreach ([$r['phone'] ?? '', $r['mobile'] ?? ''] as $raw) {
           $raw = trim((string) $raw);
           if ($raw === '') continue;
           $norm = sms_normalize_number($raw);
           if (strlen($norm) >= 13) {
               $numbers[$norm] = $raw;   // key = নরমালাইজড → ডুপ্লিকেট বাদ
           }
       }
   }
   foreach ($numbers as $raw) {
       send_sms($raw, "Cash withdraw request: Tk 5000 by rahim");
   }

 ৫. OTP পাঠানো ও যাচাই — সবচেয়ে সহজ উপায়
────────────────────────────────────────────────────────────────────
 // পাঠানোর পেজে:
 require_once '<path>/Core/SmsConfig.php';

 if (otp_send_sms($phone, 'login')) {
     echo "OTP পাঠানো হয়েছে";
 } else {
     echo "পাঠানো যায়নি (লিমিট শেষ বা নম্বর ভুল)। বাকি: " . sms_remaining($phone);
 }

 // যাচাই করার পেজে (ইউজার কোড দিলে):
 require_once '<path>/Core/SmsConfig.php';

 if (otp_verify($_POST['otp'], 'login')) {
     echo "OTP সঠিক ✅";
 } else {
     echo "OTP ভুল বা মেয়াদ শেষ ❌";
 }

 * 'login' হলো purpose — একই সেশনে আলাদা কাজে আলাদা নাম দিন:
   'login', 'reset', 'admin', 'signup' ইত্যাদি। তাহলে একটার OTP
   আরেকটার সাথে মিশে যাবে না।

────────────────────────────────────────────────────────────────────
 ৬. আলাদা করে করতে চাইলে (নিজে কোড বানিয়ে পাঠানো)
────────────────────────────────────────────────────────────────────
 $code = otp_generate('reset');   // হ্যাশ সেশনে থাকে, প্লেইন রিটার্ন
 send_otp_sms($phone, $code);     // SMS এ প্লেইন পাঠান
 // ভেরিফাই: otp_verify($input, 'reset');

────────────────────────────────────────────────────────────────────
 ৭. সব হেল্পার ফাংশন (এক নজরে)
────────────────────────────────────────────────────────────────────
 ── OTP সম্পর্কিত ──
 otp_send_sms($phone, $purpose)   → OTP বানাও+হ্যাশ+SMS, একসাথে (bool)
 otp_generate($purpose)           → OTP বানাও, হ্যাশ সেশনে রাখো (string)
 otp_verify($input, $purpose)     → কোড মেলাও (bool), সফলে মুছে যায়
 send_otp_sms($phone, $code)      → নির্দিষ্ট কোড SMS পাঠাও (bool, লিমিট আছে)

 ── জেনারেল / নোটিফিকেশন ──
 send_sms($phone, $message)       → যেকোনো মেসেজ পাঠাও (bool, লিমিট নেই)

 ── লিমিট / সহায়ক ──
 sms_can_send($phone)             → এখন OTP পাঠানো যাবে কিনা (bool)
 sms_remaining($phone)            → OTP আর কয়বার পাঠানো যাবে (int)
 sms_normalize_number($phone)     → 88 প্রিফিক্সসহ নম্বর (string)
 otp_expire_minutes()             → OTP মেয়াদ মিনিটে (int) [৫]

 ★ send_otp_sms vs send_sms পার্থক্য:
   send_otp_sms → "OTP-xxx" ফরম্যাট, 30 মিনিটে 3 বার লিমিট মানে।
   send_sms     → যা মেসেজ দেবেন তাই যায়, কোনো লিমিট নেই। নোটিফিকেশন /
                  অ্যালার্টের জন্য এটা — কারণ ওগুলো সবসময় পৌঁছানো দরকার।

────────────────────────────────────────────────────────────────────
 ৮. লিমিট / মেয়াদ বদলাতে চাইলে
────────────────────────────────────────────────────────────────────
 SmsConfig.php এর উপরে এই constant গুলো বদলান:
   OTP_EXPIRE_MIN     = 5    // OTP কত মিনিট বৈধ
   SMS_LIMIT_COUNT    = 3    // OTP কত বার পাঠানো যাবে
   SMS_LIMIT_MINUTES  = 30   // কত মিনিটের উইন্ডোতে

 * এই লিমিট শুধু OTP (send_otp_sms) এর জন্য। send_sms এতে প্রভাবিত নয়।

 ৯. লগ কীভাবে ও কোথায় রাখে (গুরুত্বপূর্ণ)
────────────────────────────────────────────────────────────────────
 সব লগ Core/ এর পাশে Logs/ ফোল্ডারে যায় (না থাকলে অটো তৈরি হয়)।

 ▶ Logs/sms_log.txt — সফল পাঠানোর রেকর্ড
     ফরম্যাট: [তারিখ সময়] SMS SUCCESS: sent to <নম্বর> | <বিবরণ>
     উদাহরণ:  [2026-09-16 06:52:10] SMS SUCCESS: sent to 8801712345678 | remaining 2
              [2026-09-16 06:53:44] SMS SUCCESS: sent to 8801812345678 | Cash withdraw request: Tk

 ▶ Logs/error_log.txt — ব্যর্থতা / লিমিট / ভুল নম্বর
     ফরম্যাট: [তারিখ সময়] SMS ERROR: <কারণ> | <নম্বর>
     উদাহরণ:  [2026-09-16 06:40:00] SMS ERROR: limit (3 per 30 min) reached | 01712345678
              [2026-09-16 06:41:10] SMS ERROR: HTTP 401 | {"..."} | 8801712345678
              [2026-09-16 06:42:00] SMS ERROR: invalid phone: 12345

 ▶ Logs/sms_limits/sms_count.json — নম্বরভিত্তিক টাইমস্ট্যাম্প
     প্রতিটি নম্বরের বিপরীতে শেষ পাঠানোগুলোর UNIX time রাখা হয়।
     এটা দিয়েই "30 মিনিটে 3 বার" লিমিট গোনা হয়। পুরনো এন্ট্রি
     অটো মুছে যায়। উদাহরণ:
       { "8801712345678": [1726450000, 1726450300, 1726450600] }

 ▶ কে লগ লেখে:
     • send_otp_sms / send_sms নিজেরাই sms_log() ডাকে — আপনাকে
       আলাদা করে কিছু লিখতে হয় না।
     • সফল হলে SUCCESS, ব্যর্থ হলে ERROR — স্বয়ংক্রিয়।

 ▶ নিরাপত্তা:
     • OTP কোড লগে কখনো লেখা হয় না — শুধু নম্বর ও ফলাফল।
     • send_sms এর ক্ষেত্রে মেসেজের প্রথম 40 অক্ষর লগে যায় (ট্রেসিং)।
       সংবেদনশীল তথ্য মেসেজে পাঠালে মনে রাখবেন।
     • সেশনেও প্লেইন OTP থাকে না, শুধু password_hash() করা হ্যাশ।

────────────────────────────────────────────────────────────────────
 ১০. নিরাপত্তা নোট
────────────────────────────────────────────────────────────────────
 • OTP হ্যাশ করা — কেউ সেশন ডাম্প পেলেও আসল কোড পাবে না।
 • এক OTP এক বারই কাজ করে (verify সফল হলে মুছে যায়)।
 • 5 বার ভুল দিলে OTP বাতিল হয়ে যায় (brute-force রোধ)।
 • Logs ফোল্ডার public থেকে ব্লক রাখুন। Logs/.htaccess এ লিখুন:
       Deny from all              (Apache 2.2)
       Require all denied         (Apache 2.4)
 • send_sms এ লিমিট নেই — লুপে পাঠানোর আগে নিশ্চিত করুন নম্বর তালিকা
   নিয়ন্ত্রিত (যেমন শুধু অ্যাডমিন), যাতে খরচ/স্প্যাম না হয়।

 ১১. দ্রুত সমস্যা সমাধান (Troubleshooting)
────────────────────────────────────────────────────────────────────
 • SMS যাচ্ছে না → error_log.txt দেখুন।
     "credentials missing" → .env এ key নেই বা VAULT_PATH ভুল।
     "invalid phone"       → নম্বর 13 ডিজিটের কম (88 সহ)।
     "HTTP 4xx/5xx"        → API key/ব্যালেন্স/URL সমস্যা।
     "limit ... reached"   → OTP লিমিট (send_sms এ হয় না)।
 • কিছুই লগ হচ্ছে না → Logs/ ফোল্ডারের রাইট পারমিশন (0755) দেখুন।
 • function not found     → SmsConfig.php include হয়নি, path যাচাই করুন।
